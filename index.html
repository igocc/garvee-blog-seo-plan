GARVEE 美国站 Blog SEO 执行方案

优化已有收录和自然搜索排名的文章，优先抓住平均排名 10–20 位的搜索机会。

执行流程内容更新工具分工八张跟踪表验收与效果判断

一、执行流程

  1. 筛选机会在 GSC 找到已有排名、值得优先优化的文章和搜索词。
  2. 看竞品，留基线确认美国搜索需求，比较竞品内容与链接，记下当前表现。
  3. 先改内容补齐读者需要的信息。按分组改稿，记录每次更新并核对上线内容。
  4. 看内容效果确认 Google 已抓取新版，到期对比点击和排名。达到目标就保留，仍有内容缺口就先补齐。
  5. 再做内链内容到位后仍需提升，就从站内相关页面补链接，记录上线日期并复看效果。
  6. 最后评估外链内链补齐并复盘后仍需提升，再参考竞品引用来源，决定是否做外链。

从改稿到链接建设，每周跟踪点击、曝光和排名。达到本轮目标就保留并转常规巡检，数据不足就约定复查日。发现文章打不开、标题截短或正文错版，先修复再推进。

原案 11 个执行步骤

01导出 GSC 数据
选择 GARVEE 美国站的 Google 网页搜索数据，导出最近 7 天完整数据的 Query + Page 明细，保留 Query、Page URL、Clicks、Impressions、CTR、Average Position，并记录日期范围。
具体操作
  1. 打开 GSC，选择 GARVEE 美国站对应的网站资源。
  2. 进入「效果 → 搜索结果」，搜索类型选择「网页」。
  3. 日期选择最近 7 天，并确认数据已完整更新。
  4. 用 Search Analytics API 同时取 page 与 query 两个维度，保留 Query、Page URL、Clicks、Impressions、CTR、Average Position。整篇文章的总点击另取页面总量。
  5. 在导出表中保留数据起止日期，后续比较时使用相同日期口径。
输出

GSC 原始数据表，作为后续 Blog 页面筛选的基础。

02筛选目标 Blog
先根据 Page URL 筛选 GARVEE Blog / Article 页面，再从对应的 Query + Page 记录中优先选择 Average Position 为 10–20 的机会。一篇 Blog 对应多个 Query 时，每个 Query 单独保留一行。
具体操作
  1. 根据 GSC 导出的 Page URL，识别页面是否为 GARVEE Blog / Article。
  2. 保留对应 Blog 页面产生的 Query，不把不同 Landing Page 的数据混在一起。
  3. 优先筛选 Average Position 在 10–20 位的 Query。
  4. 同一篇 Blog 如果对应多个 Query，每个 Query 单独保留一行，并关联同一个 Blog URL。
输出

目标 Query 与 Blog URL 对应清单，作为 SEMrush 查询和 SERP 检查的输入。

03补充 SEMrush 数据
对 GSC 初筛后的 Query，使用美国数据库查询 Volume 和 KD，并将结果补充到优化清单中。
具体操作
  1. 将筛选后的 Query 批量或逐个输入 SEMrush Keyword Overview。
  2. 数据库选择 United States。
  3. 记录每个 Query 的 Volume 和 KD。
  4. 将 SEMrush 数据按 Query 匹配回 GSC 优化清单；无法匹配或没有数据的词单独标记。
输出

补充美国 Volume、KD 的 GSC 优化清单。

04获取美国 SERP
使用固定的美国 IP、VPN 全局模式和无痕浏览器，不登录 Google 账号。逐个搜索目标 Query，记录 GARVEE 目标 Blog 的自然排名，以及排名靠前的竞争页面位置、标题和 URL，并标注页面类型。
搜索环境
  • VPN 连接美国 IP，并使用全局模式。
  • 使用无痕浏览器，不登录 Google 账号。
  • 后续如需复查，尽量保持同一美国 IP 和相同浏览环境。
具体操作
  1. 将目标 Query 输入 Google，获取美国市场自然搜索结果。
  2. 记录 GARVEE 目标 Blog 的自然排名。
  3. 提取排名靠前的自然搜索竞争页面，记录排名、标题和 URL。
  4. 标注页面类型：Blog / Article、PDP、Category 或 Review / Media。
输出

美国 SERP 竞争页面清单，供 Ahrefs 分析使用。

05分析竞争页面链接
将 SERP 前列竞争页面 URL 输入 Ahrefs，查看竞争页面的内链、外链及相关链接指标；记录 DR、UR、Backlinks、Referring Domains 等可获取数据，并与 GARVEE 目标 Blog 的链接情况对比。
具体操作
  1. 从 SERP 清单中选择排名靠前、页面类型相近的主要竞争页面。
  2. 将竞争页面 URL 输入 Ahrefs Site Explorer，按具体 URL 查看页面数据。
  3. 记录 DR、UR、Backlinks、Referring Domains 等当前报告可提供的指标。
  4. 对 GARVEE 目标 Blog 使用相同方式查询，按相同指标进行对比。
  5. 保留查询日期和目标 URL，避免不同日期的数据直接混比。
输出

Ahrefs 竞争页面链接分析表，比较 GARVEE 与竞争页面的链接基础。

06分析目标 Blog 内链
使用 Ahrefs Internal Backlinks 查看指向目标 Blog 的来源 URL、链接数量和锚文本；选取目标 Blog 用 Codex 交叉核验。核验结果基本一致且 Ahrefs 抓取范围完整后，以 Ahrefs 为主；发现遗漏或差异时，再用 Codex 补充。
具体操作
  1. 在 Ahrefs Site Explorer 输入 GARVEE 目标 Blog URL，打开 Internal Backlinks，查看指向该页面的站内链接。
  2. 记录 Inlinks 数量、来源页面 URL 和 Anchor Text；如报告提供，也记录链接属性及状态。
  3. 选取目标 Blog，用 Codex 独立抓取指向这些页面的站内链接。
  4. 按 Source URL、Target URL、Anchor Text 对照 Ahrefs 与 Codex 结果。
  5. 如果结果基本一致且 Ahrefs 抓取范围完整，后续以内链 Ahrefs 数据为主；如果存在遗漏或差异，再用 Codex 补充并核对原因。
输出

GARVEE 目标 Blog 站内链接表，分别记录内链条数和唯一来源页面数。

07记录更新前数据
每篇目标 Blog 更新前，记录对应 Query 的 GSC 点击、曝光和平均排名、美国 SERP 排名、正文长度，以及现有内链和外链数据，作为后续对比基线。
每篇 Blog 需要记录
  • 页面信息：Blog 标题、目标 URL、对应 Query。
  • GSC 数据：Clicks、Impressions、CTR、Average Position，并记录日期范围。
  • 美国 SERP：前期 SERP 检查时记录的目标页排名快照。
  • 正文长度：更新前正文英文词数（words）。
  • 链接数据：Ahrefs 获取的 Inlinks、Backlinks、Referring Domains 等数据。
输出

每篇 Blog 的更新前基线记录。

08分组更新并登记
A 组每篇文章每周更新 1 次，B 组每篇文章每周更新 2 次，C 组每篇文章每周更新 3 次。每次更新单独登记日期、修改前后正文词数及变化量、修改类型（新增、删减或改写）、修改位置和具体调整内容。
执行要求

每篇文章按所属分组的每周更新次数执行。A / B / C 组的频率、每次更新的登记要求和字段见下方「二、内容更新与分组」。

每次实际修改都单独登记到飞书跟踪表，不复制整篇文章；正文长度统一按英文词数（words）统计，不设固定增加字数。

输出

Blog 分组计划表和逐次内容更新记录。

09检查 Googlebot 抓取
由负责查看服务器日志的同事检查 Googlebot 是否重新访问目标 URL，记录访问时间和 HTTP 状态；有可核验的抓取版本或缓存更新时间时一并记录。
具体操作
  1. 将已更新的 Blog URL 和实际修改日期提供给负责查看日志的同事。
  2. 检查服务器日志中是否出现 Googlebot 对目标 URL 的访问记录。
  3. 记录 Googlebot 访问时间、请求 URL 和 HTTP 状态。
  4. 如能取得可核验的抓取版本或缓存更新时间，记录对应时间，并与内容修改时间比较。
  5. 没有日志或缓存证据时标记为待确认，不推测 Google 已抓取更新内容。
输出

Googlebot 日志与抓取验证表。

10每周跟踪 GSC 表现
GSC 数据更新后，按相同日期窗口导出目标 Query + Page 数据，记录 Clicks、Impressions、CTR 和 Average Position，与更新前基线对比。
具体操作
  1. 每周检查 GSC 是否已有完整的最新数据。
  2. 按目标 Query + Page 导出 Clicks、Impressions、CTR 和 Average Position。
  3. 与更新前基线及上一可比周期进行对比。
  4. 按 Blog URL 汇总表现；同一篇 Blog 对应多个 Query 时，保留 Query 明细，避免重复计算文章数量。
  5. 记录数据日期范围，注意 GSC 数据存在更新延迟，未完整的数据窗口不用于最终周度比较。
输出

每周 GSC 效果跟踪表，展示更新后点击、曝光、CTR 和平均排名的变化。

11决定后续优化
确认 Google 已抓取新版并完成观察。表现仍未改善时，先补内容缺口，再优先补内链；完成内链并复盘后，仍有需要再做外链。
判断顺序
  1. 先确认抓取：核对 Googlebot 是否访问目标 URL，以及是否有证据表明更新版本已被抓取。
  2. 再看 GSC：比较更新前后的 Clicks、Impressions、CTR 和 Average Position。
  3. 检查内容：如果表现没有改善，重新检查目标 Query、页面内容覆盖和竞争页面差距。有明确内容缺口时先补齐，再看同口径数据。
  4. 评估内链：内容复盘后仍有提升空间时，先用表 4 找到主题相关的站内来源页，补充指向目标 Blog 的链接。上线后检查来源页、目标页和锚文本，登记日期。
  5. 评估外链：内链补齐并复盘后，仍有提升空间时，再用表 3 的 Ahrefs 竞品数据判断是否做外链。优先考虑能自然引用文章的相关站外来源，记录实际获得的链接和日期。
输出

每篇 Blog 只登记一个当前动作：继续观察、调整内容、补内链或开展外链。写明负责人、动作日期和下一次复查日。

二、内容更新与分组

2.1 分组频率

按附件的内容更新安排执行。开始前确认每组文章、观察窗口和审核产能。

分组每篇文章每周更新次数每周登记次数
A 组1 次1 条
B 组2 次2 条独立记录
C 组3 次3 条独立记录
  • 将目标 Blog URL 分配到 A、B、C 组，并登记对应 Query、分组、开始日期。
  • 各组文章数量按本轮筛选结果和实际安排确定。
  • 每篇文章按所属分组执行更新频率，不按整个分组的文章总量计算更新次数。

2.2 每次更新登记

每次修改完成后，在飞书跟踪表中单独登记以下内容：

  • 目标 Blog URL 和实际修改日期。
  • 修改前后正文英文词数及变化量。
  • 修改类型：新增、删减或改写。
  • 修改位置及具体调整内容，例如新增产品对比、补充操作步骤或删减重复段落。
  • 执行人及修改后的版本链接。
正文长度统一按英文词数（words）统计。记录实际修改量，不设固定增加字数；不需要将整篇文章复制到跟踪表。具体字段见「表 5｜Blog 分组与更新计划」和「表 6｜Blog 内容更新记录」。

五、验收与效果判断

查看取数、上线验收与对照口径
  • GSC：固定美国 Web、设备口径和完整数据窗口。页面总量与词页明细分开，保留匿名词和数据缺失边界。
  • 上线验收：发布后核对公开页面和批准稿，重点看标题、描述和正文。分别核验 Googlebot 访问、索引和新版内容证据。缺证时继续周监控，单版本评估待确认。
  • 效果判断：完整 7 天用于预警。单次内容改动可用等长 28 天比较并参考同期未改文章。把改内容、补内链、获得外链的日期分别登记；多个动作落在同一观察窗时，按组合效果解释。
  • 更新频率：若要比较 A／B／C 效果，事先固定内容量、分配方式、未改对照和评估窗口。链接动作也要统一规则，否则合并解释。
